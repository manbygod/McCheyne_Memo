# 맥체인 성경읽기

맥체인 읽기표로 매일 말씀을 읽고, 구절을 선택해 복사·메모·공유하는 바닐라 JS 웹앱.

## 실행 방법
빌드 불필요. `file://` 로 열면 `fetch`가 막히므로 로컬 서버로 실행합니다.

```bash
cd McCheyne
python -m http.server 8000      # 또는: npx serve .
# http://localhost:8000
```

## 기능
- 날짜별 4트랙 읽기 목록(일부 장은 절 범위 표기) → 장 클릭 시 본문 (한국어 개역한글/English BSB 선택)
- 구절 클릭(복수, Shift+클릭으로 범위) → 음영 + 왼쪽 세로선, 복사 / 메모
- 본문에서 메모가 연결된 절은 번호가 배지로 표시되고, 클릭하면 그 절의 메모를 모두 보여 줍니다
- 메모: 다른 책·장의 말씀까지 한 구절씩 추가·제거(책/장/절 선택 + 본문 미리보기), 레이블 복수 선택, 레이블 추가/삭제, 수정, 읽기 팝업(PDF 저장과 같은 내용), 삭제(첫 줄만 보여 주는 confirm)
- 게시판: 한 페이지 4건씩 페이지 이동, 작성일 desc / 검색(단어·레이블·구절) 시 수정일 desc
- 공유: Web Share API(카카오톡·메시지·메일), 미지원 시 클립보드 복사
- 다운로드: TXT, PDF(글꼴을 내장한 텍스트 PDF — 선택·복사·검색·스크린리더 낭독 가능), 전체 또는 검색 결과

## ⚠️ 알아둘 점
### 성경 본문 저작권
개역개정(대한성서공회)과 NIV 1984(Biblica)는 아직 저작권 보호 대상이라 저장소에 포함하지 않았습니다.
- **한국어: 개역한글판(1961)** — 저작재산권 보호기간이 만료(2012~)된 공유 저작물로, `data/bible/ko/<bookId>.json`(66권, 31,101절)에 번들되어 있습니다.
  출처: [crizin/bible-db](https://github.com/crizin/bible-db)의 개역한글 데이터(원출처 대한성서공회, holybible.or.kr). 형식: `{ "1": ["1절", "2절"], "2": [...] }`.
  인격권(동일성유지·성명표시)에 따라 **본문을 임의로 고치지 말고** "성경전서 개역한글판 (대한성서공회)"로 출처를 표기하세요 (앱의 본문 화면에 표기됨).
- **개역개정·NIV(선택, 이 기기에만)** — 성경 화면의 "개역개정 파일 가져오기"·"NIV 파일 가져오기"로 본인이 가진 본문을 불러오면 브라우저 IndexedDB에만 저장되고 저장소·서버로는 전송되지 않습니다.
  형식은 책 ID를 키로 한 단일 JSON 파일 `{ "gen": { "1": ["1절", …], … }, "exo": {…} }`(각 책의 값은 개역한글 `<bookId>.json`과 같고 장 수가 책 정보와 일치해야 함)이며, 일부 책만 담아도 되고 다시 가져오면 들어 있는 책만 덮어씁니다. 가져온 뒤 상단 언어에서 "한국어 (개역개정, 이 기기)" 또는 "English (NIV, 이 기기)"를 고릅니다. NIV 파일도 같은 형식이며 절 본문만 영어입니다.
  예) 개역개정: `{ "gen": { "1": ["1절 본문", "2절 본문"], "2": […] }, "exo": {…} }`, NIV: `{ "gen": { "1": ["verse 1", "verse 2"], "2": […] } }`. 책 ID는 `data/books.json`의 `id`(예: gen, mat)이고, 66권 전체 또는 일부를 담을 수 있습니다.
  가져온 개역개정 본문으로 쓴 메모에는 그 구절 본문이 포함되므로, 로그인(클라우드 동기화) 중이면 메모와 함께 본인 계정 저장소에 올라갑니다.
- **English: Berean Standard Bible (BSB)** — 2023-04-30 공유 저작물로 공개된 현대 영어 번역으로, `data/bible/en/<bookId>.json`(66권)에 번들되어 있습니다.
  출처: [bereanbible.com](https://bereanbible.com) 공식 텍스트(`bsb.txt`) — "This text of God's Word has been dedicated to the public domain."
  원문에서 사본에 없는 절(예: 마 17:21, 행 8:37)은 빈 문자열로 두어 절 번호를 유지하며, 화면에는 표시하지 않습니다.
  개역한글과는 일부 장(삼상 30, 시 72, 아 6, 고후 13, 요삼 1)의 절 구분이 다릅니다. 메모는 작성한 언어의 절 번호를 저장합니다.
- NIV는 저작권 보호 대상이라 번들하지 않습니다 (NIV 1984는 현재 합법적으로 열람 가능한 온라인 사이트도 없음).

### PDF 글꼴 (Noto Sans KR 부분집합)
PDF는 이미지가 아니라 진짜 글자로 만들며, `fonts/NotoSansKR-subset.ttf`(+ 글리프 지표 `NotoSansKR-subset.json`)를 PDF 만들 때 불러와, **실제로 쓰인 글자만** 다시 잘라 PDF에 내장합니다.
- 글꼴: [Noto Sans KR](https://fonts.google.com/noto/specimen/Noto+Sans+KR) Regular(400), SIL OFL 1.1 (`fonts/LICENSE-NotoSansKR.txt`). 굵은 글씨는 같은 글꼴에 윤곽선을 덧그려 표현합니다.
- 포함 글자: KS X 1001(한글 2,350자·기호, 한자 제외) + ASCII·라틴·문장부호 + 개역한글·BSB 본문과 `data/memos.json`에 쓰인 글자. 글꼴에 없는 글자는 PDF에서 `?`로, 이모지는 빠집니다.
- 다시 만들 때(개발용, 앱 실행에는 불필요): `pip install fonttools` 후 `python scripts/gen-pdf-font.py <NotoSansKR[wght].ttf 경로>`

### 읽기표
`data/plan.json`은 2026 맥체인 성경 읽기표(365일 × 4트랙)입니다.
형식: `days["2026-01-01"] = [{book, chapter, chapter2?, verse1?, verse2?} × 4]` (`book`은 `data/books.json`의 `id`).
다른 해에는 월-일로 대응하며 2/29는 2/28과 같습니다. 이전 근사값 플랜(`"MM-DD"` 문자열 형식, `scripts/gen-data.js`로 생성)도 앱이 읽을 수 있습니다.

### 메모 저장 위치
정적 사이트는 `data/` 에 파일을 쓸 수 없으므로:
1. 메모는 브라우저 localStorage에 저장
2. `data/memos.json`에 메모 배열을 넣어 커밋하면 초기 데이터(시드)로 사용되어 기존 메모와 병합됩니다. (앱에는 JSON 내보내기/가져오기 버튼이 없으며, 필요할 때 Claude로 브라우저 저장소의 메모를 JSON으로 꺼내거나 이 파일에 추가합니다.)
3. **Firebase 동기화 (Google 로그인)**: `data/firebase-config.json`(웹 앱 설정, 공개되어도 안전)이 있으면 헤더에 "Google 로그인"이 나타납니다.
   로그인하면 메모가 `users/{uid}/memos`에 저장되어 같은 계정의 모든 기기와 동기화됩니다 (최신 수정 우선, 삭제도 동기화). 레이블 목록은 빈 레이블까지 포함해 `users/{uid}/meta/labels`에 한 문서로 저장되며 더 최근에 바꾼 쪽이 이깁니다.
   로그아웃하면 공용 PC 보호를 위해 이 기기의 메모를 지웁니다 (클라우드에는 남음). 설정 파일이 없으면 로컬 전용입니다.

### AI 질문 (Gemini 챗봇)
로그인하면 헤더에 "AI 질문"이 나타납니다. 본문(지금 읽는 장 / 선택한 날짜의 읽기표)과, 켜 둔 경우 내 메모를 참고해 질문에 답합니다.
- **구조**: 서버 코드 없음. 브라우저 → Firebase AI Logic → Gemini Developer API. 프로젝트는 **Spark(무료) 요금제를 유지**하세요. 결제(Cloud Billing)를 연결하면 무료 한도 보호가 사라집니다.
- **대화는 저장하지 않습니다.** 새로고침·로그아웃하면 사라집니다. 하루 질문 횟수(30회)는 브라우저 안의 보조 한도라 서버가 강제하지 않습니다. 실제 상한은 Gemini 무료 구간의 프로젝트 할당량이며, 다 쓰면 챗봇만 일시적으로 멈춥니다.
- **보내는 데이터**: 질문, 참고 본문(번들된 개역한글·BSB만. 가져온 개역개정·NIV는 보내지 않음), "내 메모를 참고해서 답하기"를 켠 경우 관련 메모 최대 60개(24,000자, 메모에 붙은 성경 본문은 제외). 메모 옵션은 창을 열 때마다 꺼집니다. 무료 구간은 입력 내용이 서비스 개선에 쓰일 수 있다고 알려져 있으니 [Gemini API 약관](https://ai.google.dev/gemini-api/terms)을 확인하세요. **Gemini API에는 보낸 프롬프트를 지우는 기능이 없어** 이 앱에서 전송된 내용을 삭제할 수 없습니다(앱은 대화를 서버에 저장하지 않고 요청마다 한 번 보낼 뿐입니다). 그래서 화면 안내에서 민감한 메모는 체크하지 말라고 알립니다. 로그 보관까지 없애려면 결제 연결과 서버가 필요한 Vertex AI의 데이터 무보관 설정을 써야 합니다.
- **외부 의존(CDN)**: `chat.js`가 처음 열릴 때 `https://www.gstatic.com/firebasejs/11.10.0/`의 `firebase-ai.js`(와 App Check 사용 시 `firebase-app-check.js`)를 불러옵니다. 기존 로그인·동기화는 10.12.2를 쓰므로, 챗봇은 같은 설정으로 별도 Firebase 앱(`mccheyne-ai`)을 만들어 씁니다. 빌드·npm 의존성은 없습니다.

### 기도방 (헤더의 "기도", `prayer.js`)
Google 로그인한 사람만 쓸 수 있습니다. 처음 "기도"를 열 때만 `prayer.js`를 불러옵니다. 권한은 로그인한 계정의 이메일(구글이 확인한 것)로 나뉩니다.

| 권한 | 계정 | 할 수 있는 일 |
| --- | --- | --- |
| 슈퍼관리자 | `manbygod@gmail.com` (`prayer.js` 의 `SUPER_ADMIN_EMAIL`, `scripts/firestore.rules` 의 `isSuper()` 에 같은 값) | **모든 기도방**의 모든 권한(보기·만들기·편집·삭제·모든 기도제목 편집) + **"관리자 관리"**: 관리자 권한을 계정에 부여·편집·삭제 |
| 관리자 | 슈퍼관리자가 "관리자 관리"에서 등록한 계정 (Firestore `prayerAdmins/{이메일}` 문서) | 기도방 만들기(CSV·빈 방), 그리고 **자기가 만들었거나 구성원으로 들어가 있는 기도방**에 대한 관리(이름·초대 계정 고치기, 기도방 삭제, 모든 기도제목 편집·삭제) + 사용자 기능. 그 밖의 기도방은 목록에도 나오지 않음 |
| 사용자 | 기도방에 초대된 지메일 | 검색, 게시, 편집(자기 기도제목만) |

- **검색**: 기도방 → 기도 게시자(전체·개별·복수) → 게시 날짜(전체·기간·최근 게시) → 카드로 표시. "최근 게시"는 **게시자마다 마지막으로 올린 날짜**의 기도제목입니다. 카드마다 복사·공유(이모지로 꾸민 글, 게시자·게시일 등 글자 이름도 함께), 결과가 2건 이상이면 "결과 N건 전체 복사·공유"(번호 📌 1/N 과 구분선 ━━━ 으로 건마다 나눔), 내 기도제목에는 편집(편집 화면으로 연결).
- **게시**: 기도방을 고르고 기도제목을 쓰면 게시 날짜는 오늘로 자동 입력됩니다.
- **편집**(사용자는 내 기도제목만, **관리자는 자기가 관리하는 기도방의 모든 기도제목** — 관리자는 게시자도 고를 수 있고, 남의 기도제목을 저장해도 원래 게시자의 지메일은 그대로 둡니다): 날짜(전체·기간·최근)로 찾아 카드마다 복사·공유·편집·삭제·저장·닫기. 기도제목을 고치면 게시 날짜가, 기도응답을 고치면 기도응답 날짜가 오늘로 바뀝니다. 기도응답도 여기서 올립니다.
- **기도방 만들기**(관리자): "CSV로 기도방 만들기"는 이 기기의 CSV 파일을 불러와 Firestore에 올리고, "빈 기도방 만들기"는 파일 없이 이름·관리자 이름·초대 계정만으로 내용이 빈 기도방을 만듭니다(스키마는 같고 기도제목만 없으며, 이후 게시하면 쌓입니다). 이름은 파일 이름이 기본값이며 고칠 수 있습니다. **관리자 본인의 이름도 입력**합니다(필수, CSV의 같은 이름 게시자의 기도제목이 내 것으로 연결되고 게시자 기본값이 됩니다). 초대할 사람은 **지메일 계정과 이름을 각각 입력해 한 명씩 추가**합니다(둘 다 필수, 같은 계정을 다시 넣으면 이름만 바뀜). 이름이 CSV의 같은 이름 게시자와 같으면 그 기도제목의 지메일 필드가 채워져 "내 기도제목"으로 인식됩니다. 나중에 초대한 사람은, 초대할 때 적은 이름과 게시자가 같고 지메일이 비어 있는 기도제목을 내 것으로 봅니다.
- **기도방 관리**(관리자, 슈퍼관리자는 모든 방): 자기가 만들었거나 구성원인 기도방만 목록에 나옵니다. 검색·게시·편집의 기도방 목록도 같은 범위입니다(관리하지 않는 방은 아예 보이지 않음). 이름 변경, 초대 계정 추가(지메일 + 이름)·편집·삭제, 기도방 삭제(안의 기도제목 포함), **CSV로 내보내기**("기도방 삭제" 오른쪽 버튼: 그 기도방의 기도제목을 가져오기와 같은 4칸 형식 CSV로 저장. 게시일은 기도제목 마지막 수정일의 날짜이고 오래된 것부터이며, 지메일·기도응답 일시는 담지 않습니다. 그대로 "CSV로 기도방 만들기"에 다시 쓸 수 있습니다. 한글 엑셀이 바로 열도록 UTF-8 BOM을 붙이고, 엑셀에서 수식으로 실행될 수 있는 시작(`=` `+` `@`, 붙어 있는 `-`)은 앞에 `'`를 붙여 막습니다). 관리자가 여러 명이어도 서로 다른 관리자의 기도방은 읽지도 고치지도 못합니다(서버 규칙이 막음). 다른 관리자의 기도방에 구성원으로 초대되면 그 방은 관리할 수 있습니다. 내가 만든 방이 아니면 내 계정을 구성원에서 뺄 때 관리 권한도 함께 사라집니다.
- **관리자 관리**(슈퍼관리자만, "기도방 관리" 오른쪽 버튼): 관리자로 등록할 **지메일 계정과 이름**을 입력해 추가하고, 등록된 관리자의 계정·이름을 편집하거나 권한을 삭제합니다. 계정을 바꾸면 새 계정이 관리자가 되고 예전 계정의 권한은 사라지며, 그 계정이 만든 기도방의 "만든 사람"도 새 계정으로 옮깁니다(구성원 목록과 올린 기도제목의 지메일은 그대로). 권한을 삭제하면 그 계정이 만든 기도방은 남고 슈퍼관리자만 관리할 수 있습니다. 슈퍼관리자 계정 자체는 이 목록으로 바꿀 수 없고 코드·규칙에서만 바꿉니다.

#### 기도방 CSV 형식
첫 줄(머리글)은 반드시 아래 4칸이고, 인코딩은 UTF-8 또는 한글 엑셀의 기본 CSV(CP949)를 자동으로 알아봅니다.

```csv
게시자,게시일,기도 제목,기도 응답
홍길동,2025/06/28,"ㅇ 첫째 줄, 쉼표가 있어도 큰따옴표로 묶으면 됩니다
ㅇ 둘째 줄 (줄바꿈도 큰따옴표 안에서는 그대로)",ㅇ 기도응답은 비워 둬도 됩니다
김은혜,2025/06/30,"기도 제목만 있어도 됩니다",
```

- **게시자**: 필수, 40자 이내. **게시일**: 필수, `2025/06/28`·`2025-06-28`·`2025.6.28` 형식(실제 있는 날짜). **기도 제목**: 필수, 5,000자 이내. **기도 응답**: 선택, 5,000자 이내.
- 쉼표·줄바꿈이 들어간 칸은 `"..."`로 묶고, 그 안의 큰따옴표는 `""`로 씁니다. 파일은 1MB·2,000건 이내.
- 게시자·게시일·기도 제목이 모두 없고 `ㅇ`만 남은 줄(엑셀 서식 잔여물)은 건너뜁니다. 그 밖에 형식이 맞지 않으면 **팝업창에 불가한 이유**(줄 번호와 사유)를 보여 주고 기도방을 만들지 않습니다. 모든 기도방이 같은 형식이라 머리글이 다르면 거부됩니다.
- 실제 기도 내용이 담긴 CSV·엑셀은 공개 저장소에 올라가지 않도록 `.gitignore`에 `data/*.csv`, `*.xlsx`를 넣어 두었습니다.

#### 기도방 DB 스키마 (Firestore)
- `prayerRooms/{방}`: `name`, `members[]`(초대한 지메일, 소문자), `memberNames{}`(이메일의 `.`을 `,`로 바꾼 키 → 이름), `createdBy`, `createdAt`, `updatedAt`
- `prayerRooms/{방}/prayers/{기도}` — **모든 기도방이 같은 6개 필드** (규칙이 다른 필드를 거부):

| 필드 | 뜻 |
| --- | --- |
| `author` | 게시자 |
| `authorEmail` | 지메일 (가져온 기도 중 초대 때 이름을 적지 않은 사람은 빈 문자열) |
| `contentUpdatedAt` | 기도제목 마지막 수정일시 (ISO 8601 `toISOString()`). 화면의 "게시 날짜"는 이 값의 날짜입니다. CSV로 가져온 기도는 게시일 정오로 저장 |
| `content` | 기도제목 |
| `responseUpdatedAt` | 기도응답 마지막 수정일시 (응답이 없으면 빈 문자열) |
| `response` | 기도응답 |

#### 기도방 설정 체크리스트 (콘솔에서 직접)
- [ ] **Firestore → 규칙**에 최신 `scripts/firestore.rules`(기도방 규칙 포함)를 붙여넣고 게시. 게시하지 않으면 기도방 읽기·쓰기가 모두 거부됩니다.

## GitHub Pages 배포 메모
1. 저장소 루트에 `index.html`, `style.css`, `app.js`, `chat.js`, `prayer.js`, `data/` 를 push (`McCheyne` 폴더 내용이 저장소 루트가 되게)
2. Settings → Pages → Source: `Deploy from a branch`, Branch: `main` / `(root)`
3. `https://<user>.github.io/<repo>/` 에서 확인. 모든 경로가 상대경로라 하위 경로에서도 동작
4. `data/firebase-config.json`은 올리지 않으면 로컬 모드로 동작 (404는 무시됨)
5. 공유(Web Share)는 HTTPS 필요 — Pages는 기본 HTTPS
